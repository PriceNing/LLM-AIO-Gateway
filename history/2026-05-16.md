# 2026-05-16 改动记录

## 图片/多模态支持修复

### 背景
用户报告 Codex 和 OpenCode 通过网关发送图片时模型无法识别。

### 问题根因

1. **MiniMax**: 所有 API 端点（`/v1/chat/completions`、`/v1/text/chatcompletion_v2`、Anthropic `/v1/messages`）均不支持图像输入。`MiniMax-Text-01`（文档中的多模态模型）在此账号下不可用。`provider_type` 从 `anthropic` 切换为 `openai`，`api_base` 改为 `https://api.minimaxi.com/v1`。

2. **llamacpp**: 模型本身支持视觉，但有两层问题：
   - **max_tokens 不足**: llama.cpp reasoning/thinking 模式消耗 token 配额，导致可见内容被截断。`MIN_IMAGE_MAX_TOKENS = 2000` 自动提升。
   - **OpenCode 客户端**: AI SDK 默认认为自定义模型不支持图片，需在 `opencode.json` 中声明 `modalities: {input: ["text", "image"]}`。

3. **图片格式非标准**: 某些客户端可能将图片 data URI 嵌入文本内容而非使用标准 `image_url` content part，导致 vision encoder 不被激活。

### 代码改动

#### `app/services/lite_llm.py`

- **新增 `_extract_image_data_uris(content)`**: 用正则从字符串中提取 `data:image/<type>;base64,...` 格式的图片数据 URI
- **新增 `_normalize_image_content(messages)`**: 扫描消息中的文本内容，将 data URI 转换为标准 `image_url` content part。对所有 role（user/assistant/tool）生效，适用于字符串和数组两种 content 格式
- **更新 `_has_image_content()`**: 除 `image_url` / `input_image` 类型外，还会检测文本中的 data URI
- **4 个 completion 函数** (`create_chat_completion` / `create_chat_completion_stream` / `create_completion` / `create_completion_stream`): 调用前先执行 `_normalize_image_content(messages)`，确保 `_has_image_content` 能正确检测

#### `app/router/proxy.py`

- **新增 `_debug_msg_types(messages)`**: DEBUG 级别日志，输出每条消息的 content type 结构，用于排查客户端消息格式问题。挂载在 `/chat/completions` 端点

#### 数据库

- MiniMax provider: `provider_type` → `openai`，`api_base` → `https://api.minimaxi.com/v1`

### 各模型图像支持状态

| 模型 | 状态 | 备注 |
|------|------|------|
| llamacpp | 支持 | prompt_tokens ~800，正确识别图片 |
| DeepSeek | 不支持 | 纯文本模型 |
| MiniMax | 不支持 | API 层面不暴露视觉能力 |

### OpenCode 配置

llamacpp 在 OpenCode 中需显式声明多模态能力：

```json
"models": {
    "llamacpp": {
        "name": "llamacpp",
        "limit": {"output": 4096, "context": 128000},
        "modalities": {"input": ["text", "image"], "output": ["text"]}
    }
}
```
